# ScamShield — five-slide pitch outline

## 1. A message creates pressure. The next step needs clarity.

For Indian smartphone users and family members helping them. Electricity-disconnection, KYC, delivery, remote-access and payment-refund scripts can push people into fast decisions. A person needs a clear response without having to research several reporting routes under pressure.

Source: I4C’s financial cyber-fraud reporting description, https://i4c.mha.gov.in/ncrp.aspx. Do not add unsupported incident counts or a made-up “3-hour gap”.

## 2. Screenshot in. Evidence and a recovery plan out.

ScamShield extracts screenshot text on-device or accepts pasted text, links, VPAs and phones. It prepares an evidence-led verdict, context-dependent steps, editable complaint and bank drafts, a family alert, evidence PDF and reminder calendar. User reviews and submits.

Show the actual checker and a completed case.

## 3. The agent makes its work visible.

Understand → mask sensitive numbers → classify → plan → verify in parallel → deterministic score → triage A/B/C → draft → user approval → deliver. Optional AI supplies constrained classification and native tool-calling; required checks and scoring stay under code control. Each tool result and failure appears in the trace.

Show the trace and the transition from prevention to money-lost priority actions.

## 4. Measured locally, with clear limits.

25/25 authored text fixtures matched the expected taxonomy, including 5 Hindi and 5 Marathi. These are synthetic functional regressions, not a real-world accuracy study. The median rules-only analysis + Hindi PDF build was about 0.97 seconds across five local runs; there is no measured manual baseline. Show the separate screenshot fixture report and any misses honestly.

Security/API tests cover PII masking, deterministic scoring, prompt injection, internal URL isolation, payment triage, approval-gated export, SSE, and the aiKart runner contract. Live provider calls and Docker still need deployment validation.

## 5. Practical prototype. Evidence-first growth path.

Current stack: React/Vinext, FastAPI transport, shared JavaScript engine, D1/SQLite, Tesseract OCR, pdf-lib. Fifteen reference brands and twelve curated keyword patterns. No automatic filing or contact. Unverified never means safe.

Next: real consented/redacted sample evaluation, stronger multilingual OCR on real screenshots, validated domain/reference updates, bank integrations with explicit permission, and a moderated intel network. Shared reports and guaranteed recovery are not current features.
